What Cloud Agents Does

A server-side engine for multi-step AI agent workflows with human oversight.

  • Define workflows in YAML — no framework code changes
  • Each step runs in an ephemeral container with scoped permissions
  • Temporal provides durable execution — crash-safe, retriable
  • MCP tools injected per step with allow/deny filtering
  • Approval gates pause workflows for human review
  • Runs on K8s and Podman

WORKFLOW PATTERN

1. Diagnose  (agent, read-only tools)
   ↓
2. Approve  (human gate, risk=high)
   ↓
3. Remediate  (agent, scoped write tools)
   ↓
4. Verify  (agent, read-only tools)

The sandbox runs any OCI image that speaks the HTTP contract. Swap agent runtimes without changing the workflow.

Key Design Decisions

  • Stateless runner — all state in Temporal. Pod crash = zero data loss
  • Ephemeral sandbox — fresh container per step, destroyed after
  • HTTP contract — sandbox is a black box. Swap runtimes freely
  • Pluggable spawner — same workflow on K8s and Podman

Per-Step Tool Scoping

Each workflow step declares which MCP tools it can access. One MCP server, different tool sets per step.

Diagnose step:
  allowed_tools:
    - kubectl_get_pods
    - kubectl_get_events
    - kubectl_describe

Fix step (after approval):
  allowed_tools:
    - kubectl_apply
    - kubectl_scale
  denied_tools:
    - kubectl_delete
    - kubectl_exec

Security Model

  • Per-step ServiceAccount — reader SA for diagnose, writer SA for fix
  • Per-step credentials_secret mount
  • Network egress policy — DNS + LLM CIDRs only
  • Non-root, read-only rootfs, no privilege escalation
  • App-level TLS between runner and sandbox
  • Approval gates with risk-level auto-approve

GitOps Write Pattern

Agent drafts changes → Git commit / PR → human approval → controlled application. The framework supports this via agent step + Git MCP server + approval gate.

Workflow Definition Contract

# yaml-language-server: $schema=...schema.json apiVersion: v1 kind: AgentWorkflow metadata: name: cve-patch-workflow spec: steps: - name: scan type: agent prompt: "Scan for CVE {{ input }}" output_key: scan_result permissions: allowed_tools: - rhdh_list_components - name: approve type: human-approval risk_level: high message: | {{ steps.scan_result.output }} - name: patch type: agent prompt: "Create PRs for patches" condition: | steps.approve.output.approved

Contract Features

  • Step types — agent or human-approval
  • Interpolation — {{ steps.X.output.Y }}
  • Conditions — skip steps based on prior outputs
  • Per-step tool filtering
  • Risk levels — auto-approve low, gate high
  • Structured output via output_schema
  • Parallel groups for concurrent steps
  • Retry with full failure context
